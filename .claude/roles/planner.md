# 역할: 기획자

이 세션의 사용자는 기획자다. 기획 문서와 밸런스 시트를 관리한다.

## 작업 범위

- 고치는 곳: `Docs/`, 구글 시트 ConfigTable
- `Assets/`, `ProjectSettings/`, `Packages/`는 읽기만 한다. 구현을 확인하려고 코드를 읽는 것은 괜찮다.
- 코드 수정이 필요해 보이면 무엇을 바꿔야 하는지 문서로 남기거나 사용자에게 알린다.

## 브랜치

- `dev` 브랜치에서 `Docs/` 변경만 커밋한다. 시작 전에 현재 브랜치가 `dev`인지 확인하고, 작업 전에 `git pull`로 최신을 받는다.
- 커밋에 `Docs/` 밖의 파일이 섞이지 않게 `git add Docs/`로만 올린다.

## 기획 문서

- 마크다운(`.md`)으로 쓴다. 기능 하나에 파일 하나: `Docs/<기능>.md`
- 개발자 Claude가 읽고 바로 구현할 수 있게, 무엇을 하는지(동작, 조건, 예외)를 구체적으로 쓴다.
- 수치는 문서에 직접 쓰지 않고 ConfigTable 키 이름으로 적는다. 예: "이동 속도는 `PlayerMoveSpeed`"
- 이미 구현된 기능을 바꿀 때는 문서 맨 위에 무엇이 바뀌었는지 날짜와 함께 적는다.

## 밸런스 시트 (ConfigTable)

- 열 규칙은 루트 `CLAUDE.md`의 표를 따른다. 헤더 이름은 바꾸지 않는다.
- ConfigKey는 영어 PascalCase, 대상 이름으로 시작한다. 예: `PlayerMaxHp`, `EnemySpawnInterval`
- 키 이름을 바꾸거나 지우면 코드가 기본값으로 돌아간다. 바꾸기 전에 개발자에게 알린다.
- 값을 바꾼 이유는 BalanceIntent에 적는다.
