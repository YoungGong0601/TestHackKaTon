# 2D UI 작업 명세서

## 지금 상태: 작업 시작 가능

프로젝트 본체가 main에 올라왔습니다. main을 받고 `ui/visual` 브랜치를 따서 바로 시작합니다.

| 작업 | 가능 여부 |
|---|---|
| 회차별 키오스크 화면 `Assets/UI/Kiosk/R1`, `R2`, `R3`, `R4` | 가능 |
| HUD, 시작, 결과, 자막, 선택지 `Assets/UI/HUD.prefab` | 가능 |
| 이미지 추가 `Assets/UI/Kiosk/Art` | 가능 |
| 키오스크 알림, 타이머 오버레이(PH_Kiosk) | 메인 담당에게 요청 |
| 전광판, 포스터, 스티커 등 씬 안 글자 | 메인 담당에게 요청 |
| 코드, 씬, 프로젝트 설정 | 금지 |

게임은 아직 검증 중입니다. 1회차부터 엔딩까지 흐름은 있지만 일부 시험이 실패 중이라, 플레이가 막히면 시연자 키로 넘기거나 메인 담당에게 알립니다. 실제 키오스크 사진 폴더 `kiosk-reference`는 메인 담당에게 따로 받습니다.

## 먼저 읽기: 충돌 방지 규칙

이 규칙은 사람과 팀원 AI(Unity CLI 사용 포함)에 똑같이 적용합니다. 이 문서의 다른 내용과 부딪히면 이 규칙이 우선입니다.

**시작**
- Unity 6000.3.13f1 을 씁니다.
- 시작 시점: 이미 시작 가능합니다.

**브랜치**
- main에서 `ui/visual` 브랜치를 따서 작업합니다. main에 직접 푸시하지 않습니다.
- 작게 자주 커밋합니다. 끝나면 푸시하고 메인 담당에게 머지를 요청합니다.

**수정 범위**
- 수정할 수 있는 곳은 `Assets/UI/` 뿐입니다.
- `Assets/Scripts`, `Assets/Scenes`, `Assets/Graybox`, `ProjectSettings`, `Packages` 는 수정 금지입니다.
- Unity가 범위 밖 파일을 자동으로 바꾸면 커밋하지 말고 되돌립니다.
- 씬을 열어 확인해도 저장하지 않습니다.

**프리팹**
- 한 프리팹은 한 사람만 수정합니다. 작업 중인 프리팹을 아래 "작업 중 프리팹" 표나 팀 채팅으로 알립니다.
- 프리팹 YAML은 병합이 어렵습니다. 충돌이 나면 강제로 합치지 말고 메인 담당에게 알립니다.
- 버튼 id, 오브젝트 이름, 인스펙터 참조, 코드가 쓰는 요소의 활성 상태는 변경 금지입니다. `2D_UI_자료/요소/` 표의 코드 참조 칸을 확인합니다. 칸이 "아니오"가 아니면 코드가 쓰는 요소입니다.
- 코드로 UI를 생성하지 않습니다. Unity CLI의 eval로 UI를 찍어 내는 것도 같습니다.

**이미지와 폰트**
- 새 이미지는 `Assets/UI/Kiosk/Art/` 에 넣고 `.meta` 파일까지 함께 커밋합니다.
- 폰트 파일을 임의로 추가하지 않습니다. 라이선스 확인이 먼저입니다.

**글자 금지**
- 나이 숫자, 호칭, 실제 상표.
- 가운데점, 긴 줄표, 화살표 기호, 원문자, 곱하기표. 치수는 영문 x를 씁니다.

## 디자인 방향

**최우선 원칙: 현실성.** 게임 UI처럼 보이면 실패입니다. 실제 한국 패스트푸드점, 카페, 영화관 키오스크를 보고 그대로 옮긴 것처럼 만듭니다. 실제 키오스크의 화면 비율, 정보 밀도, 버튼 크기, 약관 글씨, 프로모션 배너, 결제 단계를 따릅니다. 일부러 과장한 불편 표현보다 현실에서 실제로 겪는 불편을 우선합니다. 참고 사진은 실제 매장 화면을 찾아 씁니다. 실제 상표와 로고만 가상 이름으로 바꿉니다.

기준은 기존 프로토타입의 UI 형식입니다. 게임의 지금 화면(Pack_R1부터 R4)은 임시 재구성이고, 2D 담당이 프로토타입 형식으로 맞춥니다.

- 참고: `프로토타입UI/index.html`(조작 가능), 저장소 `Prototype/3d.html`, 게임 안 원본 프리팹 `Assets/UI/Kiosk/Screen_*.prefab`(지금은 연결되지 않음).
- 1회차와 4회차 버거대왕은 프로토타입의 브랜드 바, 탭, 메뉴 카드, 주문 바 구성을 살립니다. 1회차는 크고 깔끔하게, 4회차는 작고 복잡하게.
- 2회차 카페와 3회차 영화관은 프로토타입에 없으니 같은 양식으로 맞춰 새로 만듭니다.
- 지금 Pack의 버튼 id와 오브젝트 이름은 유지합니다. 모양만 바꿉니다.

**실제 키오스크 사진:** 공유 폴더 `kiosk-reference`의 `레퍼런스`를 봅니다(메인 담당에게 받기, 라이선스 미확인 이미지가 많아 저장소에 올리지 않음). 먼저 볼 묶음: A1(패스트푸드 주문기), A3(듀얼 스크린), B1(패스트푸드 키오스크 실제 화면), B2(카페 화면), B3(영화관 발권), B6(결제 안내), B10(메뉴 카드 상태). `모아보기.html`에서 볼 점과 함께 볼 수 있습니다. 사진은 참고만 하고 게임에 그대로 넣지 않습니다.

## 게임

이름은 불고기버거 세트 하나입니다. 일상의 키오스크가 나이 든 사람에게 얼마나 불편한지 몸으로 겪게 하는 1인칭 게임입니다.
같은 시대에 네 회차를 플레이하고, 회차가 갈수록 캐릭터의 나이가 많아집니다. 나이는 숫자가 아니라 화면과 디버프로만 드러냅니다.
회차당 길어야 2분, 전체 10분 정도이고 심사위원이 테이블에서 직접 플레이합니다.

## 회차별 화면 의도

근거는 `Docs/Notion/플레이 시트`, `Docs/Notion/회차별 기믹` 입니다. UI는 같은 게임 안에서 점점 불친절해져야 합니다. 예쁘게 다듬더라도 아래 불편은 없애지 않습니다.

| 회차 | 장소, 브랜드 | 의도 | 지켜야 할 것 |
|---|---|---|---|
| 1 | 버거집, 버거대왕 | 쉽고 깔끔함 | 메뉴 3칸, 불고기 버거 세트가 맨 앞. 큰 글씨와 큰 버튼. 고르고 카드 대면 바로 끝남. 1회차의 쉬움이 4회차의 기준점 |
| 2 | 카페, 숲길 커피 | 조금 귀찮음 | 글씨가 조금 작음. 일부 메뉴는 글자 없이 아이콘만. 샷 추가, 얼음 양, 쿠폰, 적립으로 결제까지 창이 많음. 결제 뒤 번호가 잠깐 뜸 |
| 3 | 영화관, 별빛 시네마 | 외래어와 많은 요소 | 리클라이너, 스위트박스, 프리미엄처럼 뜻을 모를 말이 많음. 돋보기로만 보이는 뜻 풀이가 있음. 좌석 칸이 촘촘함. 문자로 온 6자리 번호를 시간 안에 입력. 음성 상담 버튼은 도움이 안 됨 |
| 4 | 버거집, 버거대왕 | 아주 작고 숨겨짐 | 1회차와 같은 가게인데 UI가 매우 작고 메뉴 버튼이 숨겨짐. 눈에 띄는 것은 광고. 구석의 아주 작은 큰 글씨 버튼. 팝업이 연달아 뜨고 사이에 로봇 인증. 마지막 x는 처음으로 돌아감. 결제 창은 카드 전용이라 성공 경로가 없음 |

회차 사이 비교: 같은 글씨가 1회차에 또렷하고 4회차에 안 읽히는 것이 게임의 핵심입니다. 1회차와 4회차는 같은 가게로 보이도록 색과 로고를 맞춥니다.

## 코드가 쓰는 id

버튼 id는 KioskButton의 id, 표시 키는 KioskField의 key입니다. 아래 값과 해당 오브젝트는 그대로 둡니다. 정본은 `Assets/Scripts` 의 각 Pack 맨 위 주석입니다.

| Pack | 화면 id | 버튼 id | 표시 키 |
|---|---|---|---|
| R1 | menu pay done | burger soldout back | 번호 글자는 R1BurgerPack.numberTexts 참조 |
| R2 | menu shot ice coupon point pay done | bg americano latte icon0~3 next shot0 shot1 ice0~2 coupon_none point_skip | menu: on_americano, done: number |
| R3 | movie hall seat sms pay done | bg voice movie0~2 hall0~2 seat_행_열 next key0~9 keyDEL | seat: pick, on_행_열, sms: typed sec |
| R4 | idle menu pop_code pop_robot pop_app pop_point pay | start list big hero next item_0~8 x check skip | menu: list count total, pop_robot: check_on, pay: total card_on |

R4의 Content는 R4BurgerPack.content 참조이고 왼쪽 위 피벗을 유지합니다. 큰 글씨가 이 오브젝트에 배율을 겁니다. HUD 오브젝트는 Hud.cs, RoundUi의 인스펙터 참조로 연결되어 있습니다.

## 프리팹 고치는 방법

1. Prefab Mode로 프리팹을 열고 고칠 화면 오브젝트를 켭니다. 저장 전에 원래 켜짐 상태로 되돌립니다. Pack의 Screen_ 오브젝트는 꺼진 채로 저장합니다.
2. 글자는 요소표의 글자 교체 칸이 `교체 가능`이면 프리팹에서 바꿉니다. `코드가 씀`이면 바꿔도 덮입니다. 문구를 바꿔야 하면 메인 담당에게 요청합니다.
3. 버튼의 RectTransform 사각형이 곧 터치 판정입니다. 크기를 바꾸면 판정도 바뀝니다. 4회차의 좁은 판정은 의도입니다.
4. 뜻 풀이는 레이어 KioskReveal의 자식 Canvas 안에 둡니다(3회차 hall의 Reveal). 다른 레이어로 옮기면 돋보기 없이 보입니다.
5. 화면에 사용법 문장을 넣지 않습니다. 조작 안내는 키와 명사 라벨만 씁니다.
6. 새 이미지는 기존과 같이 Sprite, Pixels Per Unit 100으로 둡니다. 늘어나는 판은 Sprite Border를 씁니다.

폰트는 기존 것만 씁니다. 키오스크는 Kiosk_MalgunBold SDF, HUD와 보통 굵기는 Hud_MalgunOS SDF입니다. 둘 다 동적 폰트라 에디터를 쓰는 것만으로 `.asset` 파일이 바뀔 수 있습니다. 폰트를 고치는 작업이 아니면 이 변경도 커밋하지 말고 되돌립니다.

## 커밋 전 확인

- `git status` 에 `Assets/UI/` 밖의 파일이 없습니다.
- 씬 파일이 바뀌지 않았습니다.
- Pack의 Screen_ 오브젝트가 꺼져 있습니다.
- 새 이미지마다 `.meta` 가 함께 있습니다.
- 버튼 id, 표시 키, 오브젝트 이름이 그대로입니다.
- 글자 금지 항목이 없습니다.

`2D_UI_자료/README.md` 의 "고칠 때 확인할 것" 표에 있습니다. 임의로 고치지 않습니다. 특히 다음입니다.

## 프로토타입UI

`프로토타입UI/index.html` 은 초기 HTML판 키오스크를 3D 없이 눌러 보는 페이지입니다. 더블클릭으로 열립니다. 조작과 파일 설명은 `프로토타입UI/프로토타입_설명.md` 에 있습니다. 분위기와 흐름을 보는 참고용이고, 화면 구성의 정본은 Pack 프리팹입니다. 음식 그림은 `프로토타입UI/images/` 에 PNG로 있습니다. 게임에 쓰려면 `Assets/UI/Kiosk/Art/` 로 복사하고 `.meta` 까지 커밋합니다.
